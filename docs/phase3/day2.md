### 새 AI 요약 (강남구 역삼1동 커피음료점) — 비교

**Before (Day 1):**
> 역삼1동은 3만4천 명의 인구에 30~40대가 절반을 차지하는 수요처이지만, 반경 500m 내 172개 커피점이 밀집해 있어 포화 경쟁이 심한 상황이네요. 임대료 정보 부재와 함께 종합 점수 27점(우려)은 신규 진입 시 충분한 검토가 필요함을 시사합니다.

**After (Day 2):**
> 역삼1동은 **강남구 평균보다 인구가 1.35배 많은데도** 커피점 적합도가 동 단위로 **중위권(12위)에 그친 게 눈에 띄네요**. 더 흥미로운 건 수요 점수 86점의 상당 부분이 30~40대 집중(+14.1%p)에서 나온다는 거라, **거주층보다는 직장인·방문 수요가 핵심**이라는 뜻일 수 있어요. 반경 500m에 172개 경쟁점이 있는데 시군구 감소 추세라는 건 **이미 포화 상태에서 약한 업체들이 빠져나가고 있다는 신호**로 보여요. 임대료 데이터 부재가 판단을 어렵게 하지만, 수요는 충분해 보여도 그걸 잡아낼 수 있는 입지·가격대의 균형을 현장에서 꼼꼼히 확인하실 필요가 있을 것 같습니다.

별명도 분석적: `30대 밀집 역삼, 수요 대비 경쟁 역전 지점`

## 발견 — 3가지

### 1. ✅ 비교 컨텍스트가 LLM 깊이의 핵심
prompt 에 단순 통계만 주면 LLM 도 "인구 많네요" 평범한 말. **시군구 평균 대비 위치 + 행정동 안 업종 순위 + 같은 업종 행정동 순위** 4가지 비교 지표를 input 에 추가하니 "1.35배", "12위", "역전 지점" 같은 통찰이 자연스럽게 나옴.

→ `web/src/lib/llm-client.ts` 의 `CompareContext` interface + `web/scripts/build-llm.ts` 의 `buildCompareContext()` 사전 계산.

### 2. ⚡ 병렬 5호출로 빌드 5배 빠름
- Sequential (Day 1): 4.5초/call × 2,178 = 163분 (2.7시간) — 너무 김
- Parallel 5 (Day 2): 약 33분 — 운영자가 기다릴 수 있는 시간
- Anthropic Haiku 분당 한도 안에서 안전 (5 동시 = 분당 약 60-70 호출)

### 3. ✂️ 단순화 = 정보 명료화
운영자 피드백: "처음 보는 사람 입장에서 정보 과부하". 4섹션 제거 후 핵심만 남으니 첫인상 ↑. 시뮬레이터도 3시나리오 대비 단일 결과가 사용자 의도 (직접 입력한 값으로 결과 보기) 와 일치.

## 제안 — Day 3+ 옵션

| 옵션 | 작업 | 비용 | 기간 |
|---|---|---|---|
| A | **서울 25구 풀빌드** | ~\$48 (6만원) | background ~10시간 |
| B | **인기 5업종 전국** (커피/한식/편의점/미용실/치킨) | ~\$13 (1.7만원) | background ~3시간 |
| **C** ★ | **on-demand 모드** — 첫 방문 시 호출 + 캐시 (Vercel KV 또는 fs) | runtime 비용 (월 사용량) | 1일 |
| D | **점수 알고리즘 정밀화** — 임대료 0점 너무 단순 (시군구별 분위 등) | $0 | 반나절 |
| E | **prompt A/B 테스트** — 다른 톤·길이 비교 후 선택 | 추가 호출 비용 | 반나절 |

추천 흐름: **D (점수 정밀화) → C (on-demand) → A 또는 B**.

이유:
- D 는 LLM 호출 안 하고 점수 logic 만 — 비용 0, 결과 더 정확
- C 는 일괄 빌드 비용 폭주 막음 (실제 사용 페이지만 호출)
- A/B 는 C 도입 후 자연스럽게 채워짐
