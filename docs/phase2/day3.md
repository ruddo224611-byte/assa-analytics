# Phase 2 Day 3 — 창업 시뮬레이터 (BEP 3시나리오)

**날짜:** 2026-04-27
**작업:** 리포트 #5 섹션의 placeholder → 실 시뮬레이터로 교체. CLAUDE.md MVP #5 ⭐ 완성.

---

## 결과

🟢 **시뮬레이터 동작.** 사용자 입력 4개로 즉시 3시나리오 BEP 자동 계산.

### 입력 (사용자 4개만)
- 평수 (기본 30평)
- 객단가 (업종별 기본값 자동 — 카페 6,000원 / 한식 12,000원 / 미용실 25,000원 등)
- 일 손님 (기준)
- 인건비 월 (기본 250만원)

### 자동 적용
- **임대료**: R-ONE 의 1층 데이터 자동 (천원/㎡ × 평수 × 3.305785)
- **재료비율**: 업종별 표준 (카페 30%, 편의점 70%, 미용실 15% 등 17개 업종)
- **기타 고정비**: (월세 + 인건비) × 15% (관리비·공과금·소모품)
- **3시나리오 손님**: 기준 × 1.5(낙관) / 1.0(기준) / 0.6(보수)

### 출력 (3 시나리오 카드)
- 월 매출 / 월 영업이익 / BEP 손님 / 달성률 %
- 적자 시 빨간색 + "⚠ 적자 — 손님 수·객단가 조정 필요" 메시지
- 색상: 낙관 emerald · 기준 brand · 보수 slate (적자 시 rose)

## 발견 — 3가지

### 1. 업종별 기본값 — 카페 사장 직관 + 통념 기반 17개 작성
정확한 산업 평균 데이터 X 라 운영자 (카페 사장) 직관 + 일반 통념으로 시작:
- 카페 객단가 6,000원 / 재료비 30%
- 한식 12,000원 / 35%
- 미용실 25,000원 / 15%
- 편의점 5,000원 / 70%
- 등 17개 + default fallback

→ **운영자 검토 권장.** 본인 카페 데이터로 비교해서 어색하면 수정 부탁.

### 2. 임대료 매핑 없는 행정동 처리
R-ONE 매핑이 없는 행정동 (예: low confidence 도 안 잡힌 외곽) 은 **시뮬레이터 자체 안 보여줌** + amber 안내 메시지.

### 3. 시나리오 multipliers 단순화
처음엔 "사용자가 낙관/기준/보수 손님수 다 따로 입력" 고려했으나 너무 복잡. → **기준만 입력 + 자동 ±50%**. 결과 충분히 의미 있고 입력 부담 적음.
