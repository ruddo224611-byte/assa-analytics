## 발견

### 1. H 형식 (시군구 1 파일 nested) 압축 효과 87%

| 같은 강남구 | Day 1 (행정동·업종 분리) | Day 2 (H 형식) |
|---|---|---|
| 파일 구조 | 22 행정동 폴더 × 99 파일 = 2,178 파일 | 1 파일 (nested) |
| 디스크 | 8.5 MB | 1.07 MB |

**압축 이유:** 행정동 단위 공통 데이터 (수요·임대료·지원사업) 가 99 업종에 중복되던 게 1번으로. 업종별로는 경쟁 정보만 남김.

→ PR diff 도 22,000 파일 → 250 파일로 줄어 운영자 검토 가능.

### 2. 휴리스틱 false positive 발견·수정

자동 reference 생성 시 처음에 **"황학동(중구)"** 이 "학동" 키워드 매칭으로 강남구청역 매핑되는 사고. **"같은 구 zone 만 매칭"** 규칙 추가로 해결.
- 매핑 결과: 175개 high (키워드 매칭) + 252개 low (구 fallback)
- Phase 2 라벨링 시 low 부분 운영자 검수 권장

### 3. 행정동명 vs 일반인 동명 차이 (UX 우려)

샘플 검증 중 발견:
- "성수1가1동" 입력 시 jumin 데이터엔 "성수1가제1동" 로 들어가있음
- "화곡1동" → "화곡제1동"
- "잠실3동" → "잠실제3동" (지금은 "잠실3동" 으로도 매칭됨, 이건 케이스 바이 케이스)

→ Phase 2 UI 검색 시 "성수동" 처럼 단순 입력해도 모든 "성수1가제N동" 보여주는 매칭 필요. 핵심 UX 이슈.

### 4. 직관적 인사이트 사례 (운영자 카페 사장 관점에서 흥미로울 것)

- 마포구 (홍대 포함) 커피음료점 1,342개 / **YoY -6.9%**. 강남구 -1.7%, 영등포 옷가게 -8.8% 와 비교. 카페 시장 마포 특히 빠르게 줄고 있음 (홍대 카페 시장 포화 신호?)
- 명동 한식 415개 / **YoY +0.6%** (관광지 회복 신호)
- 신림 pc방 15개 (학생 동네지만 적음)
- 영등포역 옷가게 391개 (의류 메카)
