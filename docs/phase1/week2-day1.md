## 발견 (작업하면서 알게 된 4가지)

### 1. 중심 좌표 결정 방식 차이 → 결과 미세 변동

| 빌드 방식 | 역삼1동 카페 500m 결과 |
|---|---|
| Week 1 (build-data.ts) — 중심 = 역삼역 하드코딩 | **177건** |
| Week 2 (build-batch.ts) — 중심 = 동 store 평균 | **172건** |

5건 차이. 둘 다 합리적 — 어떤 게 "맞는지" 는 정의 문제. 정책 결정 필요.
- A. 행정동 중심 좌표 = 동 store 평균 (현재 batch)
- B. 행정동 중심 좌표 = 동 centroid (정확한 폴리곤 중심) — 추가 데이터 필요
- C. 사용자가 지도에서 직접 클릭한 위치 — Phase 2 UX 설계

### 2. 외곽동 데이터 신뢰도 표시 필요

세곡동 약국 3건, 개포1동 편의점 5건 등 외곽동은 store 자체가 적음. 데이터 정확하지만 **"표본 작음"** 신뢰도 표시가 UI 에 필요. 현재 산출물 `meta.신뢰도` 에 명시 안 됨.

### 3. SBIZ 호출 시군구당 76회 → 전국 250 시군구 = ~19,000회

**일 한도 10,000회 초과.** 풀빌드 시 **시도별 분할 (1일에 1~2개 시도)** 필수.
- 서울 (25 구) ~ 1,900회
- 광역시 6개 ~ 600회
- 도 9개 ~ 16,500회 (군 단위 많음)

→ Week 3 cron 설계 시 시도별 분할 cron 트리거 필요.

### 4. ⚠️ 디스크 폭발 위험 — 풀빌드 시 데이터 폭증

| 단위 | 디스크 |
|---|---|
| 강남구 (22 행정동 × 99 업종) | **8.5 MB** |
| 서울 (25 구 추정) | ~200 MB |
| 전국 (~250 시군구 추정) | ~**2 GB** |

git repo 에 commit 시 문제 큼:
- repo 크기 폭증
- PR diff 폭발 (운영자 검토 불가능)
- Vercel deploy 시 cloning 시간 증가
- 매월 갱신 시 매번 2,178 (또는 22,000) 파일 diff

**풀빌드 진행 전 디스크 전략 결정 필수.**

| 옵션 | 장점 | 단점 |
