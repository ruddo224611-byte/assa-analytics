### 누적 발견사항 (Phase 2 인계)

1. **디스크 전략 H** — 시군구 1 파일 nested 구조. 풀스케일 169MB / 255 파일 (검토 가능 규모)
2. **시군구명 충돌** — 같은 이름 다른 시도 ("남구" 5개 광역시) → (시도, 시군구) 튜플 매칭
3. **세종 특수 케이스** — 시군구 layer 없음 + NTS 가 "세종시" → reference 통일
4. **SBIZ rate limit (429)** — 일 한도 외 분당/시간 한도 더 빡빡. 자동 60→120→180초 재시도
5. **Background stuck 위험** — 1.5-2시간 작업은 끊길 가능성. Week 3 cron 에서 시도별 분할 + 진행 알림 필수
6. **R-ONE 매핑 정밀도** — 광역시·도 모두 low confidence (대표 상권 1개 fallback). **Phase 2 운영자 라벨링 필요**
7. **행정동명 표기 차이** — "성수1가1동" vs "성수1가제1동", "우1동" vs "우제1동". **Phase 2 UI 퍼지 매칭 필요**
8. **경기도 jumin 시·구 layer** — "수원시 장안구" 같이 시·구 합본 시군구명. 정규식 + NTS 일치 사전 검증 통과

### Phase 2 (리포트 페이지) 인계 핵심 사항

**입력 데이터 형식:**
```
data/build/{시도}/{시군구}.json  (255 파일)
└── meta { 시도, 시군구, 기준일, 신뢰도 }
└── 행정동 { 동명: { 지역, 수요, 임대료, 지원사업_links, 업종별: {업종: {경쟁}} } }
```

**Phase 2 UI 가 처리해야 할 UX 이슈:**
- 행정동명 퍼지 매칭 (사용자 입력 정규화)
- R-ONE 임대료 신뢰도 라벨 ("상권 기준, 매핑신뢰도 low" 등)
- 외곽동 표본 작음 표시 (세곡동 약국 3건 같은 케이스)
- 시군구명 충돌 — 사용자가 "남구" 검색하면 "어느 광역시?" 묻기

**Phase 2 시작 전 운영자 라벨링 권장:**
- R-ONE 상권 매핑 정밀화 (특히 광역시·도 시군구) — Phase 2 UI 만들면서 같이 진행 가능
