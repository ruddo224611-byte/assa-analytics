## 발견 — 4가지

### 1. 시군구명 충돌 (남구·동구·북구) — 수정함
부산/대구/인천/광주/울산 모두 "남구" "동구" 같은 시군구 있음. 처음 build-batch 가 시군구명만 받아서 5개 광역시 데이터가 한 파일에 섞일 위험 발견.
→ **(시도, 시군구) 튜플** 로 받게 수정.

### 2. 세종 특수 케이스 2개 동시 발견·수정
- jumin 패턴이 `"세종특별자치시  조치원읍"` (공백 2개) — 정규식 공백 매칭 `+` 로 수정
- NTS 데이터가 시군구를 **"세종시"** 로 적음 (region 의 "세종" 과 불일치) → region-codes 의 시군구를 "세종시" 로 통일

→ 세종 조치원읍 카페가 처음엔 시군구내 업소수 NULL 이었는데 fix 후 **646개 (YoY -3.4%)** 정상 매칭.

### 3. 광역시 R-ONE 매핑 모두 low (= 광역시별 대표 상권 1개만)
서울처럼 키워드 매칭 X. 광역시별 fallback 1개씩만:
- 부산 → 서면/전포
- 대구 → 동성로중심
- 인천 → 구월
- 광주 → 금남로/충장로
- 대전 → 둔산
- 울산 → 삼산동
- 세종 → 조치원

→ 광역시 사용자 입장에선 임대료가 "광역시 대표 상권 평균" 이라 정확도 낮음. 신뢰도 메타에 `low` 명시됨. **Phase 2 라벨링** 에서 정밀화.

### 4. 행정동명 표기 차이 (또 발견)
사용자 입력 "우1동" 시 jumin 데이터엔 "우제1동". Day 2 의 "성수1가1동 vs 성수1가제1동" 과 동일 패턴. **Phase 2 UI 퍼지 매칭 필요** 재확인.
