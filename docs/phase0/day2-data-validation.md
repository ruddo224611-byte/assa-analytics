## TASK 1 — 상가업소 정보 API 검증

### 1-1. 공단 상가(상권)정보 관련 API 목록

공공데이터포털을 뒤져보면 "소상공인시장진흥공단 상가(상권)정보" 계열은 실질적으로 **3갈래**로 나뉘어 있음:

| 구분 | 호스트 / 네임스페이스 | 성격 | 현재 키로 접근 |
|---|---|---|---|
| **A. 통계 API** | `api.odcloud.kr/api/15083033/v1/*` | 전국/지자체 업종별 업소수 추이, 경기동향 등 집계 리포트 | ✅ 200 OK |
| **B. 반경/행정동 조회 API** | `apis.data.go.kr/B553077/api/open/sdsc2/*` (baroApi) | `storeListInRadius` / `storeListInDong` / `storeListInArea` — 개별 상가 POI | ❌ 403 Forbidden |
| **C. 파일데이터 (분기 덤프)** | data.go.kr > 15083033 파일데이터 | 분기별 전국 상가업소 CSV 전량 (~200만 건/분기) | 수동 다운로드 |

우리가 기획한 **"반경 500m 카페 검색"** 은 B 유형인데, 현재 키는 B 호출이 막혀있음. A는 집계만, C는 오프라인 벌크라 실시간 사용자 입력 대응 불가.

### 1-2. 실제 호출 검증

**A. 통계 API — 정상 작동**

```
GET https://api.odcloud.kr/api/15083033/v1/uddi:363ece31-09ac-47e2-85b1-bdbd25f19618
    ?page=1&perPage=10&serviceKey=***
```

응답 요약 (`docs/phase0/samples/sangga-sample.json` 참고):

```json
{
  "currentCount": 10,
  "data": [
    { "구분": "1", "기준월": "201512", "업소수": "66889" },
    { "구분": "2", "기준월": "201606", "업소수": "60707" },
    { "구분": "3", "기준월": "201612", "업소수": "72096" }
    // ...
  ],
  "matchCount": 10,
  "totalCount": 34
}
```

- 총 34건 (2015-12 ~ 2019-09 분기별 전국 카페 업소수)
- 필드: `기준월`, `업소수` — 사실상 시계열 집계만.

**B. 반경 조회 API — 403 Forbidden**

```
GET https://apis.data.go.kr/B553077/api/open/sdsc2/storeListInRadius
    ?serviceKey=***&radius=500&cx=127.036380&cy=37.500640&type=json

→ HTTP 403 · "Forbidden"
```

현재 키(`PUBLIC_DATA_API_KEY`) 로는 B553077 네임스페이스가 활성화되어있지 않음. 공공데이터포털에서 "**소상공인시장진흥공단 상가(상권)정보**" OpenAPI 를 **별도 활용신청**해야 함.

### 1-3. 기획했던 항목 vs 실제 확인 결과

| 기획한 확인 항목 | 15083033 (통계) | B553077 (POI, 현재 403) |
|---|---|---|
| 결과 개수 | 월당 전국 1건 (집계) | (활용신청 후 확인) |
| 업종 코드 체계 (대/중/소분류) | ❌ 없음 (업종명만 텍스트) | 대분류 `indsLclsCd`, 중분류 `indsMclsCd`, 소분류 `indsSclsCd` (스펙 상) |
| 좌표 정밀도 (경위도) | ❌ 좌표 자체 없음 | EPSG:4326 소수점 6자리 (스펙 상) |
| 최신 업데이트 기준일 | 2019-09 까지 (정체) | 분기 단위 갱신 (스펙 상) |
| 건물명, 지번/도로명, 층 | ❌ 없음 | 있음 (`storeListInRadius` 응답 필드) |

### 1-4. 🔴 판정 — 활용신청 필요

현재 상태로는 **MVP 의 핵심 기능(사용자 입력 → 반경 상가 리스트)을 구현할 수 없음**. 통계 집계만으로는 "역삼동 500m 안에 카페 몇 개?" 를 답할 수 없음.

**액션 아이템:**
1. data.go.kr 에서 "소상공인시장진흥공단 상가(상권)정보" OpenAPI 활용신청 — 보통 1~2영업일 내 승인
2. 승인 확인 후 `scripts/fetch-sangga.ts` 의 `fetchStoresInRadius` 가 그대로 동작 (변경 불필요, 이미 작성됨)
3. 임시 대안: C(파일데이터) 를 받아서 DB 로 로드 → 자체 반경 쿼리. 단 2M 행 × 분기 수동 동기화 부담 큼

## TASK 2 — 행정안전부 주민등록 인구 CSV 검증

### 2-1. 다운로드 경로

공식 UI: https://jumin.mois.go.kr/ageStatMonth.do (행정동별 연령별 인구현황)

브라우저 버튼 "csv 파일 다운로드" 를 뜯어보면 내부적으로 다음 POST 요청을 수행:

```
POST https://jumin.mois.go.kr/downloadCsvAge.do?searchYearMonth=month&xlsStats=3

form-data:
  searchYearStart=2026, searchMonthStart=03
  searchYearEnd=2026,   searchMonthEnd=03
  sltOrgType=1, sltOrgLvl1=A          # 전국
  sum=sum, gender=gender              # 합계 + 성별 포함
  sltArgTypes=10                      # 연령구간 = 10세 단위
  sltArgTypeA=0, sltArgTypeB=100      # 0 ~ 100세
  state=3                             # 전체 읍면동 현황
  category=month
```

- 로그인 불필요. 응답: `application/octet-stream`, 인코딩 **EUC-KR (CP949)**, 약 **1.16MB**
- 기준월 2026-03 기준 **3,918 행정동** 행
- Node 기준 `iconv -f EUC-KR -t UTF-8` 또는 스크립트에서 `TextDecoder('euc-kr')` 로 변환 필요

### 2-2. 컬럼 구조

헤더 (40 컬럼):

```
"행정구역",
"2026년03월_계_총인구수", "2026년03월_계_연령구간인구수",
"2026년03월_계_0~9세", "2026년03월_계_10~19세", ..., "2026년03월_계_100세 이상",
"2026년03월_남_총인구수", "2026년03월_남_연령구간인구수",
"2026년03월_남_0~9세", ..., "2026년03월_남_100세 이상",
"2026년03월_여_총인구수", "2026년03월_여_연령구간인구수",
"2026년03월_여_0~9세", ..., "2026년03월_여_100세 이상"
```

| 확인 항목 | 결과 |
|---|---|
| 집계 단위 | ✅ **행정동** (법정동 아님). 행정동 코드가 `"행정구역"` 값 안에 괄호로 포함 — 예: `서울특별시 강남구 역삼1동(1168064000)` |
| 연령대 5세 단위 | 🔴 **미제공** (이 CSV 는 `sltArgTypes=10`, 즉 10세 단위만). 폼 파라미터를 5 로 바꿔보는 건 추후 확인 필요. 기본 제공 다운로드는 10세 단위 |
| 성별 구분 | ✅ 계 / 남 / 여 |
| 세대수 컬럼 | 🔴 **없음** — 이 데이터셋은 인구만. 세대수는 **별도 데이터셋** `주민등록 인구 및 세대현황` (jumin.mois.go.kr/statMonth.do) 에서 받아야 함 |
| 법정동 버전 | 필요 시 공공데이터포털 15108071 (openapi) — 법정동(행정동 통반단위) 인구/세대 |

### 2-3. 역삼동 실제 값 (2026-03 기준)

`docs/phase0/samples/jumin-sample.csv` 에 포함됨.

| 행정구역 | 행정동 코드 | 총인구 | 남 | 여 | 20~29세 | 30~39세 | 40~49세 |
|---|---|---|---|---|---|---|---|
| 서울특별시 강남구 역삼1동 | 1168064000 | 34,113 | 16,729 | 17,384 | 6,029 | 9,720 | 6,153 |
| 서울특별시 강남구 역삼2동 | 1168065000 | 35,980 | 16,736 | 19,244 | 4,178 | 4,426 | 7,844 |
| **역삼동 합계 (추정)** | — | **70,093** | 33,465 | 36,628 | 10,207 | 14,146 | 13,997 |

관찰:
- 역삼1동은 20~30대 쏠림(2030 = 15,749명, 전체의 46%) — 오피스/싱글 성향
- 역삼2동은 40대 쏠림(7,844명, 전체의 22%) — 거주 밀도 높음

→ "같은 역삼동이어도 카페 타겟이 완전히 다름" 을 인구 데이터만으로도 바로 보여줄 수 있음 (MVP 에서 유용)

### 2-4. 🟡 판정 — 대체로 OK, 단 추가 데이터셋 필요

**좋은 점:**
- 월 1회 갱신 / 무료 / 로그인 불필요 / 프로그램적 다운로드 가능
- 행정동 단위 + 성별 + 10세 연령구간 — MVP 수요 분석에 충분한 해상도
- 행정동 코드 포함 → 공단 상가 API 의 행정동 필드와 조인 가능

**부족한 점 & 후속 조치:**
1. **5세 단위 연령구간** — 폼 파라미터 `sltArgTypes=5` 테스트 필요 (Day 3 또는 백로그)
2. **세대수** — 별도 데이터셋 다운로드 (`jumin.mois.go.kr/statMonth.do`)
3. **인코딩(EUC-KR)** 변환 처리 필수. ETL 진입점에 공통 유틸 둬야 함

### 3-3. Day 3 (국세청·부동산원) 전에 조정할 점

4. ⬜ **EUC-KR 변환 공통 유틸 구조** — ETL 스크립트가 늘어날 테니 `scripts/lib/fetch-csv.ts` 같은 공통 헬퍼 미리 뽑아둘 가치 있음.
5. ⬜ **Day 3 국세청 업종별 사업자 통계 / 부동산원 시세** 는 keyless / 또는 별도 신청 체계가 다르니, 오늘 밤 / 내일 아침에 미리 신청 상태 확인 후 시작.

## 실행 방법 (재현 가능성)

```bash
# 상가 API (현재 키로는 15083033 만 동작, B553077 는 403 예상)
npx tsx scripts/fetch-sangga.ts

# 주민등록 인구 CSV (로그인 불필요, 약 1.16MB, EUC-KR)
curl -sL -o /tmp/jumin.csv \
  -A "Mozilla/5.0" \
  --data-urlencode "sltOrgType=1" \
  --data-urlencode "sltOrgLvl1=A" \
  --data-urlencode "searchYearStart=2026" \
  --data-urlencode "searchMonthStart=03" \
  --data-urlencode "searchYearEnd=2026" \
  --data-urlencode "searchMonthEnd=03" \
  --data-urlencode "gender=gender" \
  --data-urlencode "sum=sum" \
  --data-urlencode "sltArgTypes=10" \
  --data-urlencode "sltArgTypeA=0" \
  --data-urlencode "sltArgTypeB=100" \
  --data-urlencode "category=month" \
  --data-urlencode "state=3" \
  "https://jumin.mois.go.kr/downloadCsvAge.do?searchYearMonth=month&xlsStats=3"
iconv -f EUC-KR -t UTF-8 /tmp/jumin.csv | head -1
```
